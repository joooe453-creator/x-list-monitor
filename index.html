What the skill standardizes

Instead of giving teammates a fixed list number or a rigid prompt, this skill gives their agent a reusable setup protocol.

Onboarding

Ask the purpose first

The agent asks what the list is for: news, research, security, regulation, competitor tracking, sentiment, or custom monitoring.

Cron guidance

Recommend by post volume

The agent asks expected posts/day and explains why higher-volume lists need shorter intervals to reduce coverage gaps.

Runtime agnostic

Hermes, OpenClaw, or unknown

The agent checks available tools before promising X search, scheduling, file state, dashboards, or messaging delivery.

Setup flow

Users can answer naturally. The agent turns their answers into monitoring rules and a self-contained scheduled task if requested.

Example digest output
Coverage: partial-safe
High priority · Market-moving

ETF flow update appears across multiple sources

Summarize the update, include source URL, and mention whether duplicate coverage was merged.

Medium priority · Security

Protocol exploit discussion detected

Archive exact records first, then push only if it matches the user's risk-monitoring standard.

Archive only · Low info

Routine reply or promotional post

Keep in JSONL state if collected, but suppress from alerts unless the user requested everything.

Cron frequency by volume

The skill explicitly tells agents not to promise 100% complete coverage unless the tooling supports pagination and bounded backfill.

<20/dayDaily or every 8h is usually acceptable.
20–100/dayRecommend every 4–8h.
100–300/dayRecommend every 1–4h.
300+/dayEvery 1h, split list, or tighten filters.
UnknownRun a one-time test first, then adjust.

Designed for teammates, not one fixed monitor.

List number stays empty. The skill asks each user for purpose, language, filtering standard, delivery mode, post volume, and cron preference.

Output options

Alert, digest, research, or archive

The skill includes templates for concise alerts, news digests, content research cards, and archive-only runs. It also requires coverage reporting so failed capture is never treated as “no news.”


Default language: English. Users can choose Simplified Chinese, Traditional Chinese, bilingual, or follow-original.
